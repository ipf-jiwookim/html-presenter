# 슬라이드 앵커 노트 · 내보내기/가져오기 · 발표 편의 기능 — 설계

날짜: 2026-08-18 · 대상: `index.html` (단일 파일 유지) · 상태: 사용자 승인 대기
개정: rev2 — 최종 검토에서 발견한 13건 반영 (§부록에 목록)

## 배경과 목표

같은 발표를 다른 강의장(다른 PC 포함)에서 다시 하는 상황을 지원한다.
핵심 문제 두 가지:

1. 노트가 페이지 **번호**에 묶여 있어, 덱 중간에 한 장을 끼우면 뒤 노트가 전부 밀린다.
2. 노트가 브라우저 안에만 있어, 다른 PC로 가져갈 방법이 없다.

해결 원칙: **로그인·서버·클라우드 없음.** 노트는 슬라이드 "내용"에 붙이고,
이동은 사람이 읽을 수 있는 마크다운 파일로 한다.

절대 규칙 두 개:

- **틀린 자리에 조용히 붙느니 미배정으로 남긴다.**
- **어떤 경로로도 기존 노트를 말없이 잃지 않는다.** (덮어쓰기 대신 이동·백업)

## 범위 (이번 라운드에 전부 포함)

| # | 항목 |
|---|---|
| 1 | 슬라이드 앵커 (지문 생성 + 중복 순번 + 기존 노트 마이그레이션 + 이전 노트 복구) |
| 2 | 노트 .md 내보내기 / 가져오기 왕복 (드롭존 확장자 분기, 충돌 정책, 미배정 노트함) |
| 3 | 무반응 덱 · 분리형 리소스 안내 2종 |
| 4 | 큐 시트 글씨 크기 A−/A+ · 타이머 목표 시간 |

제외(변경 없음): 로그인, 클라우드 동기화, 패키지 HTML, 유사도(fuzzy) 자동 매칭, 병합 편집기.

## 1. 슬라이드 앵커

### 1-1. 지문 생성 — `slideAnchor()`

입력: 슬라이드 엘리먼트 목록. 출력: 슬라이드별 앵커 배열(`["a3f9c1", "empty#1", …]`).

절차:

1. 각 슬라이드의 `textContent`에서 토큰 추출(공백 분리)
2. **공통 토큰 제거** — 푸터·브랜드 문구가 지문에 섞이는 것을 막는다.
   전체 슬라이드의 80% 이상에 등장하는 토큰을 스톱워드로 삼는다.
   **단, 슬라이드가 5장 미만이면 이 단계를 건너뛴다** — 짧은 덱에서는 본문 단어까지
   공통으로 잡혀 지문이 전멸한다.
3. **숫자 토큰 제거** — `P.07 / 21` 같은 페이지 카운터가 총장수 변화(21→22)로
   전 슬라이드 지문을 무효화하는 것을 막는다. 숫자를 포함한 토큰(`07`, `7/21`,
   `2026.07.23`)을 통째로 버린다.
4. 남은 토큰을 공백 1개로 이어 붙이고 소문자화
5. 32비트 FNV-1a 해시 → 6자리 hex (외부 라이브러리 없음, 동기 실행.
   `crypto.subtle`은 비동기라 쓰지 않는다)
6. 결과가 빈 문자열이면(이미지뿐인 장, 큰 숫자 하나만 있는 장) 지문은 `empty`
7. 같은 지문의 n번째 등장이면 `#n`을 붙인다(문서 순서 기준, 1부터)

**계산 시점 — 지연 계산.** 덱 스크립트가 늦게 초기화되는 경우가 있으므로 로드 시점에
미리 계산하지 않는다. 노트를 읽거나 쓸 때 `anchorFor(index)`가 그 시점의 미러 DOM에서
계산하고, `(deckName, 슬라이드수)` 기준으로 메모리 캐시한다. 슬라이드를 못 찾으면
캐시하지 않고 `null`을 반환하여 호출자가 `byIndex`로 폴백한다(다음 호출에서 재시도).

**한계 (명시)**

- 같은 내용의 슬라이드가 여럿이면 순번(`#n`)으로만 구분되므로, 그 사이에 장을
  끼우면 순번이 밀린다. 내용이 같으면 구분할 근거가 없어 불가피하다.
- 텍스트가 매번 달라지는 슬라이드(타이핑 애니메이션 등)는 지문이 흔들릴 수 있다.
  숫자 제거가 카운트업은 흡수하지만 타이핑 효과는 못 잡는다. 이 경우 노트는
  미배정 노트함으로 가고, 사용자가 재배정한다.

### 1-2. 저장 구조

```
ptnotes2:{deckName}  → JSON 한 덩어리
{
  "anchors": { "a3f9c1": "노트…", "empty#2": "…" },
  "byIndex": { "0": "…" },                          // 앵커 불가 덱 폴백
  "orphans": [ { "text": "…", "hint": "8 / 22 · 제목…" } ],
  "fontSize": 16,                                   // §4-1
  "goalMin": 45                                     // §4-2 (미설정 시 키 없음)
}
ptnotes2:{deckName}:undo → 가져오기 직전 스냅샷 1개 (§2-2)
```

- 접근은 현재의 `store`(localStorage + 메모리 폴백) 경유. 덱당 키 1개로 통합한다.
- 노트 저장은 **300ms 디바운스** 후 레코드 전체를 직렬화한다(타이핑마다 전체 쓰기 방지).
- **저장 공간 초과를 삼키지 않는다**: `localStorage` 쓰기가 실패하면(용량 초과 등)
  메모리 폴백으로 계속 동작하되 1회 경고 배너를 띄운다 —
  "브라우저 저장 공간이 꽉 차 메모를 영구 저장할 수 없습니다. 노트를 내보내 두세요."

### 1-3. 기존 노트 마이그레이션

첫 로드 때 `ptnotes2:{deckName}`이 없고 구키 `ptnotes:{deckName}:{n}`이 있으면
n번째 슬라이드의 앵커로 이관한다(앵커 불가 시 `byIndex`로). 구키는 삭제하지 않는다
(롤백 안전판).

### 1-4. 이전 노트 복구 — 파일명이 바뀐 경우

저장 키의 최상위가 파일명이므로, 파일명만 바뀌어도 레코드를 못 찾는다
(`발표자료.html` → `발표자료_최종.html`). 이때:

1. `ptnotes2:*` 레코드를 훑어 각 레코드의 앵커 집합과 현재 덱의 앵커 집합의
   **겹침 비율**을 계산한다 (`anchorOverlap(a, b)` — §2-2에서도 재사용)
2. 가장 높은 레코드가 **40% 이상**이면 제안한다 —
   "「발표자료.html」에 쓴 노트 12개가 있습니다. 이 자료의 것으로 보입니다 — [불러오기]"
3. 사용자가 수락하면 현재 덱 레코드로 복사한다(원본은 그대로 둔다)

앵커를 못 만드는 덱에서는 이 복구를 시도하지 않는다.

### 1-5. 앵커 불가 덱 폴백

`deckState()`가 구조를 못 찾는 덱은 `byIndex`로만 동작한다. 이 경우 가져오기에서
페이지 수가 다르면 자동 배정하지 않고 전부 미배정 노트함으로 보낸다.

## 2. 내보내기 / 가져오기

### 2-1. 내보내기 — 큐 시트 헤더의 [내보내기] ghost 버튼

파일명 `YYYY-MM-DD_{덱이름}_노트.md` (확장자 제거, `/ \ : * ? " < > |`는 `_`로 치환).
Blob + `<a download>`.

```markdown
# AI깐부_쇼케이스_발표자료.html — 발표 노트
<!-- html-presenter notes v1 · 21페이지 · 2026-08-18 -->
<!-- 이 파일은 자유롭게 고쳐도 되지만, slide 주석은 지우지 마세요 —
     다시 가져올 때 노트가 제자리를 찾는 표시입니다. -->

## 8 / 21 · "다섯 스킬이 PDF에서 쓰는 데이터"
<!-- slide: 7c1a9f -->
여기서 질문 받기. 시간 넘치면 생략.

## 미배정
<!-- unassigned -->
(원래 위치: 5 / 21) 예전에 쓴 멘트.
```

- 슬라이드 제목 = 해당 장 텍스트 첫 줄(40자 컷). 비어 있으면 `(제목 없음)`.
- 페이지 번호는 **사람이 읽기 위한 참고값**이며 가져올 때 사용하지 않는다.
- 노트가 있는 페이지만 기록. 미배정 노트는 `## 미배정` 섹션에 함께 내보낸다.
- 노트가 하나도 없으면 버튼을 `disabled` 처리하고 이유를 툴팁으로 보여준다.
- 덱 전체 지문은 기록하지 않는다 — 한 장만 고쳐도 값이 바뀌어 매번 경고가 뜨기 때문.
  자료 일치 여부는 §2-2의 앵커 겹침 비율로 판단한다.

### 2-2. 가져오기 — 별도 버튼 없음, 드롭존/파일선택이 확장자로 분기

- `.html/.htm` → 덱 로드(현행), `.md` → 노트 가져오기
- 덱보다 먼저 .md를 넣으면 flash: "발표 자료를 먼저 열어주세요."
- `html-presenter notes v1` 헤더가 없으면 거부 + flash:
  "이 파일은 노트 내보내기 파일이 아닙니다."

**파싱** — 섹션 경계는 **주석 마커만** 사용한다(`<!-- slide: … -->`,
`<!-- unassigned -->`). `##` 로 시작하는 줄은 경계로 쓰지 않는다 — 사용자가 노트 본문에
`##`를 적을 수 있기 때문. 한 파일에 같은 앵커가 두 번 나오면 `\n\n`으로 이어 붙인다.

**배정 규칙**

1. 앵커가 현재 덱에 있으면 그 슬라이드에 배정
2. 없으면 미배정 노트함으로
3. 파일의 앵커 집합과 현재 덱의 겹침이 **20% 미만**이면 배정 전에 확인 —
   "다른 자료에서 내보낸 노트로 보입니다. 계속할까요?"

**충돌 — 기존 노트를 지우지 않는다.** 같은 슬라이드에 내용이 다른 기존 노트가 있으면
건수를 세어 한 번만 묻는다:

- **[파일 것으로 교체]** — 기존 노트는 버리지 않고 **미배정 노트함으로 이동**시킨다
  (힌트에 "교체되기 전 노트" 표기)
- **[기존 유지]** — 파일 쪽 노트를 미배정 노트함으로 보낸다

어느 쪽을 골라도 데이터는 사라지지 않는다. 추가 안전판으로 가져오기 직전 레코드를
`ptnotes2:{deckName}:undo`에 저장하고, 완료 flash에 **[가져오기 되돌리기]** 를
30초간 노출한다.

완료 flash 예: "노트 21개 중 20개 연결 · 1개는 미배정 노트함. [되돌리기]"

### 2-3. 미배정 노트함

큐 시트 아래 접이식(`<details>`) 목록. 비어 있으면 섹션 자체를 숨긴다.
항목당 원래 위치 힌트 + 노트 앞부분과 버튼 둘:

- **[이 페이지에 붙이기]** — 현재 보고 있는 페이지에 배정. 대상에 기존 노트가 있으면
  덮지 않고 `\n\n`으로 이어 붙인다.
- **[삭제]** — 이 항목만 삭제(확인 없음, 되돌리기 스냅샷과 무관)

미배정 노트도 레코드에 저장되어 새로고침 후에도 남는다.

## 3. 안내 2종 (조용한 실패 제거)

### 3-1. 키보드에 반응하지 않는 덱

조건: **사용자의 첫 [다음]** 에서 `moved === false` 이고 `step === 0`.
구조 감지 여부와 무관하다 — 클릭 전용 덱은 `.slide` 구조는 있으면서 키보드만
안 먹는 경우가 가장 흔하므로, 구조 없음을 조건으로 걸면 정작 필요한 케이스를 놓친다.
총 슬라이드가 1장인 덱은 제외한다(정상적으로 넘길 곳이 없음).

배너(1회):

> 이 자료는 키보드 넘김에 반응하지 않는 것 같습니다. 자료를 만든 AI에게
> "← → 방향키로 슬라이드가 넘어가게 해줘"라고 요청해 보세요.

### 3-2. 분리형 리소스

덱 로드 시 `deckHTML`에서 상대경로 참조를 찾으면(`<img src>` 및 CSS
`url(...)`, `http`·`data:`·`//`로 시작하지 않는 것) 1회 flash:

> 이미지가 별도 파일로 분리된 자료입니다 — 단일 HTML로 합쳐야 이미지가 표시됩니다.

## 4. 발표 편의

### 4-1. 큐 시트 글씨 크기

큐 시트 헤더에 `A−` `A+` ghost 버튼. 13 → 16 → 20 → 24 → 28px 5단계, 덱별 저장
(`fontSize`). textarea와 다음 노트 미리보기에 함께 적용한다.
**양 끝 단계에서는 해당 버튼을 `disabled`** 처리한다(눌러도 아무 일 없는 상태를 만들지 않는다).

### 4-2. 타이머 목표 시간

- 경과 시간 클릭 → 분 단위 `<input inputmode="numeric">` 인라인 편집(모달 없음).
  `Enter` 확정, `Esc`·포커스 이탈은 취소
- **해제**: 입력창을 비우고 확정하면 목표 해제(경과만 표시 상태로 복귀)
- **검증**: 1~600(분)만 허용. 벗어나거나 숫자가 아니면 무시하고 이전 값 유지
- 설정되면 "경과" 옆에 "남은" 계측 추가: `goalMin*60 − 경과`
- 남은 5분 이하 → 앰버(`--next`)
- **도달·초과**: 라벨을 "남은"→"초과"로 바꾸고 숫자는 **양수**로 표시(`초과 02:20`).
  음수 표기(`−02:20`)는 이중 부정으로 안 읽히므로 쓰지 않는다
- **알림은 1회만**: 0을 넘는 순간 계측부 1회 펄스 + flash "목표 시간에 도달했습니다."
  이후에는 라이브 레드 색만 유지한다(계속 깜빡이면 그게 더 방해).
  `prefers-reduced-motion`이면 펄스 없이 flash만
- **소리 없음**: 노트북 오디오가 강의장 스피커에 연결된 경우 청중에게 들린다
- 타이머 일시정지 중에는 남은/초과 계산도 멈춘다. 발표를 막는 동작(정지·모달)은 없다
- 덱별 저장(`goalMin`). 리셋(↺)은 경과만 초기화하고 목표는 유지
- 미설정이면 현재와 완전히 동일한 화면. 청중 화면에는 어떤 경우에도 표시되지 않는다

## 데이터 흐름

```
덱 로드 → ptnotes2 레코드 로드(없으면 구키 마이그레이션 → 없으면 앵커 겹침으로 복구 제안)
페이지 이동/타이핑 → anchorFor(index) 지연 계산 → 앵커 키로 읽기/쓰기(앵커 없으면 byIndex)

내보내기: anchors + orphans → md → Blob 다운로드
가져오기: md 파싱(주석 마커 기준) → 앵커 대조 → 배정 / 충돌질문 / 미배정함 → undo 스냅샷
```

## 오류 처리 원칙

- 앵커 계산 예외는 `byIndex` 폴백으로 흡수 — 콘솔이 죽지 않는다
- 가져오기 파싱 실패는 flash 후 무시(기존 노트 불변)
- localStorage 쓰기 실패는 메모리 폴백 + 1회 경고 배너(§1-2). 조용히 삼키지 않는다

## 테스트 계획 (브라우저 패널 + `__ptLoad`)

1. **삽입 시나리오(핵심)**: 21장에 노트 3개 → 8번 앞에 새 장 삽입한 수정본 로드
   → 노트 3개 제자리, 새 장만 빈 노트
2. **푸터 오염**: `P.07/21` 푸터를 가진 덱에서 1 실행 — 총장수 변화에도 앵커 불변
3. **앵커 안정성**: 같은 덱을 두 번 로드 → 앵커 배열 동일
4. **짧은 덱**: 3장 덱에서 앵커가 전멸하지 않는지(스톱워드 건너뛰기 확인)
5. **중복 장**: 같은 내용 2장에 각각 다른 노트 → 새로고침 후 유지
6. **마이그레이션**: 구키만 있는 상태에서 로드 → 노트 보임
7. **파일명 변경 복구**: 같은 덱을 다른 파일명으로 로드 → 복구 제안 → 불러오기 동작
8. **왕복**: 내보내기 → 레코드 삭제 → 가져오기 → 전체 복원
9. **수정 덱 가져오기**: 한 장 고친 덱에 가져오기 → 그 장만 미배정, 재배정 동작
10. **충돌 무손실**: 다른 내용의 기존 노트에 가져오기 → 교체/유지 각각에서
    반대쪽 노트가 미배정함에 살아있는지 + [되돌리기] 동작
11. **본문에 `##` 포함한 노트** 왕복 → 섹션이 깨지지 않음
12. 무반응 덱 안내(클래스 있는 클릭 전용 덱으로), 분리형 리소스 안내
13. A−/A+ 경계 disabled, 목표 타이머(5분 앰버 · 초과 라벨 전환 · 1회 알림 · 해제 · 검증)
14. **회귀**: 마지막 장 정지, 미리보기 +1, 재동기화, 청중 창 독립 창(실 Chrome)
